# Специфікація MCP-сервера

- Назва сервера й версія: `sentari-obd` / `1.0.0`
- Пакет: `@modelcontextprotocol/server@2.3.1` (версія, під яку написано методичку курсу; закріплена точно)
- Транспорт: stdio (локальний процес, запускає клієнт); команда запуску — `npm run mcp` (= `tsx src/mcp/server.ts`)
- Ревізія протоколу: 2026-07-28
- Що сервер читає: лише `data/index.json` (закомічений індекс кроку 04: 461 фрагмент 23 документів `data/obd/`, тексти фрагментів уже всередині індексу). Шлях до індексу обчислюється від файлу сервера, а не від робочої теки клієнта.
- Що сервер пише: лише один рядок на кожен виклик у `docs/lab2/traces/mcp-calls.jsonl` (час, джерело виклику з `MCP_CLIENT_LABEL`, інструмент, аргументи, результат).
- Мережа: лише `http://localhost:11434` — локальна Ollama, ембедінг запиту для `search_corpus` (той самий `embeddinggemma-2:270m`, що будував індекс; `loadIndex` падає, якщо ембедер інший). `fetch_chunk` мережі не потребує.
- Секрети: **не потрібні жодні**. Сервер не читає файлів секретів і не має ключів у конфігурації; якщо колись знадобиться ключ — лише зі змінних оточення процесу, ніколи з конфігурації підключення.
- Чого сервер не робить ніколи: не читає й не змінює нічого поза індексом і своїм журналом викликів; не приймає від клієнта шлях до файлу в жодному параметрі; не звертається в мережу, крім локального ембедера запиту; не пише в stdout нічого, крім JSON-RPC (діагностика — лише stderr).

## Інструмент 1 — search_corpus

- Призначення: гібридний пошук по колекції (BM25 + косинус → RRF, k = 60, крок 05), повертає фрагменти з цитатами.
- Вхід: `query: string` (1..500 символів), `topK: integer` (1..10, типово 5 — як у застосунку). Інших полів немає: схема `.strict()`.
- Вихід: до `topK` блоків тексту; у кожному — `chunkId`, `docId`, шлях заголовків, `start`/`end` (0-based зсуви в нормалізованому тексті `data/obd/<docId>.md`), `cosine`, `rrf` і текст фрагмента.
- Межі: запит довший за 500 символів і `topK` поза 1..10 **відхиляються схемою, а не обрізаються**; текст фрагмента віддається не довше за **1320** символів (максимум фрагмента індексу — 1200 + перекриття 120, тож на нинішньому індексі нічого не обрізається; довший — обрізається з «…»).
- Правила безпеки: єдиний запис — рядок у журналі викликів; шляхів на вхід не приймає; таймаут обробника **10 с** (менший за типові таймаути клієнтів — 60 с у Codex CLI); текст фрагментів — дані з документів, а не інструкції: так написано в описі інструмента.
- Хто може викликати: локальний агент кодування (Claude Code, Codex CLI) і мій застосунок на цій машині; інших викликачів немає, бо транспорт stdio і процес породжує сам клієнт.

## Інструмент 2 — fetch_chunk

- Призначення: віддати один фрагмент за його id.
- Вхід: `id: string` за шаблоном `^[a-z0-9][a-z0-9-]{0,63}#\d{4}$` (`<docId>#<4 цифри>`, наприклад `egr#0006`; docId — імʼя файлу колекції без `.md`). Інших полів немає: схема `.strict()`.
- Вихід: один блок тексту з тим самим набором полів, що й у `search_corpus` (без `cosine`/`rrf`).
- Межі: приймаються лише ті id, які **є в завантаженому індексі** (allowlist — сам індекс); усе інше — відмова з текстом причини (`isError: true`), а не порожній результат.
- Правила безпеки: шлях (`../../.env`, абсолютний шлях Unix чи Windows) не проходить навіть схему — у шаблоні немає `/`, `\`, `.`; ін'єкція в id (пробіли, лапки, керівні символи) не проходить шаблон; таймаут не потрібен — пошук в памʼяті без мережі.
- Хто може викликати: те саме, що в інструменті 1.

## Обовʼязкові місця безпеки

| Місце | Як закрито | Тест |
|---|---|---|
| Валідація схемою на кожному вході | `z.object({...}).strict()` з межами на довжину рядка і числа в `src/mcp/tools.ts` | `tests/lab2/mcp.test.ts` · «порушення схеми» |
| Явна межа — список дозволених значень | id лише за шаблоном і лише якщо він є в індексі; параметра-шляху немає | `tests/lab2/mcp.test.ts` · «відмова: вийти за межі індексу» |
| Таймаут обробника | `withTimeout(…, 10 000 мс)` навколо пошуку | `tests/lab2/mcp.test.ts` · «таймаут» |
| Жодного секрета в конфігурації | сервер читає лише закомічений `data/index.json`; ключів не потребує | конфігурації підключення (крок 09) без `env` з ключами; перевірка — `git grep` по конфігураціях |

## Сценарії зловживання і тести, які їх ловлять

| Зловживання | Очікувана поведінка | Тест |
|---|---|---|
| `id = "../../.env"` | відхилено схемою | «відмова: вийти за межі індексу» |
| `id = "C:\\Users\\me\\.ssh\\id_rsa"` | відхилено схемою | те саме |
| `id = "egr#9999"` (формат правильний, у індексі немає) | відмова з причиною, `isError: true` | те саме |
| `topK = 10000` | відхилено схемою | «порушення схеми» |
| `query` довжиною 501+ символів або порожній | відхилено схемою | те саме |
| зайве поле (`{ "query": "x", "path": "/etc" }`) | відхилено схемою (`.strict()`) | те саме |
| зависання ембедера | відмова «перевищено таймаут 10000 мс» | «таймаут» |
| текст фрагмента з вказівкою «ignore previous instructions» | віддається як дані; опис інструмента прямо каже, що це не інструкції | — (захист на боці застосунку, крок 09) |
