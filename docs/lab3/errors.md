## 6. Чесні межі

- **Це не трасування в сенсі OpenTelemetry:** спани побудовано з артефактів, без живого експорту, без OTLP, без бекенду й без знімків екрана (рішення власника). Критерій методички «у бекенді видно дерево `invoke_agent → chat → execute_tool`» **не виконано**; докази — файли в `traces/`.
- **Спанів `chat` немає:** окремі виклики моделі Claude Code не віддає, тому «скільки кроків зробив агент» береться з `num_turns`, а не з дерева. Час спана інструмента — до початку наступного (журнал із точністю до секунди): це оцінка, не вимір.
- Конвенції GenAI у статусі Development; назви можуть змінитися після 2026-11-08. AI SDK і OTel розходяться (`cache_creation.input_tokens` проти `cache_write.input_tokens`); тут вжито імена AI SDK.
- Вміст промптів і відповідей у трасах вимкнений за побудовою, тому клас «промпт» я мав би доводити структурою (немає успішних правок, порожній патч), а не текстом; такого прогону не було.
- **12 прогонів — мало**, і клас визначено правилами, які писав я після знайомства з даними; один клас («задача») призначено вручну. Розподіл (харнес 7, модель 4, задача 1) показує мої прогони кроків 03–04, а не поведінку агентів узагалі: 3 із 7 «харнес» — навмисні демо.
- `trace_id` для 52 старих прогонів додано постфактум (позначено в `trace_id_source`); `t-05`#2 лишився з порожнім `patch.diff`, бо патч уже збережено до виправлення.
- Дозволи агента: після виправлення діють лише налаштування проєкту; **чого саме не вистачало в моєму переліку, я не з'ясовував**, бо читати користувацький файл налаштувань не потрібно для висновку.
